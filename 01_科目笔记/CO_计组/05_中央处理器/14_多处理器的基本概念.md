## 5.7.1 SISD、SIMD、MISD、MIMD 的基本概念

### 分类依据 按 **指令流数量** 和 **数据流数量** 来分,共4 类:

###  ①SISD(单指令流单数据流)

- 一个处理器 + 一个存储器
- 任一时刻只执行**一条**指令 
- 传统串行计算机 
- 性能提升手段:**指令流水线 + 多功能部件 + 多模块交叉存储器**
- ⚠️ 即使内部用了流水线,从外部看仍是 SISD

### ② SIMD(单指令流多数据流)

- 一个指令控制单元 + **多个处理单元**
- 所有处理单元**同时执行同一条指令**,但操作**不同数据**
- 本质:**数据级并行** 
- 典型代表:**向量处理器**
- 通过专用指令操作一维数组
- 将数据加载到向量寄存器,流水化批量处理 
- ⚠️ **短板**:遇到 switch/case 等**条件分支**,各处理单元要执行不同操作,无法保持同步,效率显著下降
- ⚠️适合**规则、同构**的数据处理

### ③ MISD(多指令流单数据流)

- 多条指令流同时处理**同一个**数据流 ，理论上存在,实际**几乎没用**,仅作概念完整性的"占位符"

### ④ MIMD(多指令流多数据流)

- 同时执行多条指令,处理多个不同数据流
- **线程级并行**
- **目前主流的并行计算模型**
- 又分两类:

| 子类              | 关键特征                  | 通信方式   |
| --------------- | --------------------- | ------ |
| **多计算机系统**      | 每个节点**私有**存储器 +独立地址空间 | 消息传递   |
| **多处理器系统**(SMP) | 共享主存 + **统一全局地址空间**   | 普通访存指令 |

### 向量处理机（SIMD思想的进阶应用）
- 一条指令的处理对象是向量
- 擅长对向量型数据并行计算、浮点数运算，常备用于超级计算机中，处理科学研究中巨大运算量
- 多个处理单元，多组向量寄存器
- 交叉多模块存储器
- 大容量，集中式主存储器

## 5.7.2硬件多线程(Hardware Multithreading)

### 为什么需要?

传统 CPU线程切换需要**保存/恢复寄存器上下文**,频繁切换开销大。
**硬件多线程**:为每个线程配备**独立的通用寄存器组、PC 等**,切换时只需激活对应寄存器组,**无需读写主存**,大幅降低切换延迟。

### 三种实现方式

#### ①细粒度多线程(Fine-grained)

- **每个时钟周期**都切换线程 
- 轮流发射各个现成的指令
- 例子:周期 i 执行线程 A 的指令 j+1,周期 i+1 执行线程 B 的指令 k+1 
- 优点:隐藏延迟,功能部件利用率高 
- 缺点:单线程执行速度变慢(总被打断)，指令级并行，线程间不并行

#### ②粗粒度多线程(Coarse-grained) -同一线程**连续执行多条指令**

- 仅当线程因**高延迟事件**(如 Cache缺失)阻塞时,才切换到另一线程 
- 连续几个时钟周期都发射同一线程的指令序列，流水线阻塞切换另一个线程
- 切换时需要**清空流水线 +重新填充**,开销通常**大于细粒度** 
- 指令级并行，线程间不并行
- 例子:线程 A出现 Cache缺失时才切到 B

#### ③ 同时多线程(SMT, Simultaneous Multithreading)

- **单时钟周期内**可**同时发射并执行**来自多个线程的多条指令
- 同时实现**指令级并行 +线程级并行**
- 构建在支持超标量和乱序执行的现代微架构上 -典型代表:**Intel 超线程(Hyper-Threading)技术**
- 单物理核维护**两套**完整线程状态部件 -高速缓存、ALU 等执行资源**共享**
- 单核上实现接近双核的并发能力,实际提升 **10%~30%**

> ⚠️细粒度和粗粒度的**核心目标都是隐藏延迟,

## 5.7.3 多核处理器(Multi-core Processor)

### 定义

将多个**独立处理单元**集成到**单个 CPU芯片**中,每个单元叫一个**核(core)**,也叫**片上多处理器(CMP, Chip Multiprocessor)**。

### 典型结构

- 每个核通常配备**私有 L1 Cache**(有时含 L2) 
- 多个核**共享更高层级 Cache**(如 L3)
- 所有核通过**互连网络共享主存**

### 关键点(408考点)

- 单核系统的细粒度/粗粒度多线程:任一时刻**只有一个**线程在运行,只是时间上交错
- 单核系统的 SMT:可在单核上**并发执行**多条指令
- **多核系统**:每个核**物理上同时执行**一个线程,实现**真正的并行处理**


> 结论:
> 
> - 多核 → 增加**处理单元数量** → **任务级并行**
> - 向量处理器 → **单指令作用于多数据** → **数据级并行**

## 5.7.4共享内存多处理器(SMP)

### 定义

具有**共享单一物理地址空间**的多处理器系统,称为**共享内存多处理器(SMP)**。

### 关键特征

- 所有 CPU 都可通过**普通访存指令**访问内存任意位置
- 通过**读/写共享变量**通信 
- 操作系统负责将各 CPU 的**虚拟地址**映射到统一的**物理地址空间**

### 两大分类

#### ① UMA(Uniform Memory Access,统一存储访问)

- 所有 CPU访问**任意**内存单元的延迟**基本相同**
- 与发起请求的 CPU 和目标地址**无关** 
- 早期典型:北桥 + 前端总线(FSB)架构

#### ② NUMA(Non-Uniform Memory Access,非统一存储访问) -内存访问延迟**取决于请求 CPU 与目标内存的物理位置**

- 主存被划分为多个区域,分别连接到不同 CPU
- 每个 CPU 直接连一部分物理内存 = **本地内存**
- 各 CPU 通过高速互连总线(如 Intel **QPI**)连接 
- 访问**本地内存延迟 <<远程内存**
- ⚠️ **程序性能对数据布局较敏感**(要把数据放在用它的 CPU 本地)
- 是为解决**前端总线争用瓶颈**而诞生的(内存控制器从北桥移到 CPU内部)


### SMP 中的关键问题

#### 1.同步问题 -多个 CPU 可能同时访问同一共享变量

- 必须引入**同步机制**,确保操作的**原子性**与**数据一致性**
- 否则可能读到另一 CPU 更新过程中的**中间值**
- **常用方法:互斥锁**
- 任一时刻仅允许一个 CPU持有该锁
- 其余 CPU 必须等待释放后才能访问

#### 2. Cache 一致性问题

- 第3 章的 Cache 一致性:针对**单处理器**中 Cache 与主存的数据同步
- SMP系统中:多个 CPU 的 Cache 可能同时缓存**同一物理内存地址**的副本
- **SMP 的 Cache 一致性要求更严格**:

> **任意时刻,所有 CPU 对该地址的 Cache副本必须保持一致**

- 实现手段:硬件一致性协议
- 通过**及时传播写操作**
- 或**无效化其他 CPU 中的副本** -维护全局数据一致性
