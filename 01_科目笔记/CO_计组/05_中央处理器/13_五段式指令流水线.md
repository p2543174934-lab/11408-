## 核心框架:统一的 5 段流水线

MIPS 所有指令都被强行塞进 **IF → ID → EX → MEM → WB** 这 5 个段,不够的就"塞空气"(插入空段)。

---

## 各指令的"本职"段

### 1️⃣ R 型(寄存器-寄存器运算,如 add)
`R[rd] = R[rs] op R[rt]`
- IF 取指
- ID 读 rs、rt
- **EX 用 ALU 算**
- WB 把结果写回 rd
- MEM 空着 ✈️

> ⏱ 4 段干活,1 段摸鱼

### 2️⃣ I 型(立即数运算,如 addi)
- 和 R 型一模一样,就是把 rt 换成 16 位**立即数(符号扩展后)**
- 同样是 4 段干活

### 3️⃣ lw(加载,读内存)
`R[rt] = M[R[rs] + SEXT(imm16)]`
- IF → ID → **EX 算地址** → **MEM 读内存** → **WB 写寄存器**
- ⏱ **5 段全用上**,这是基准选手

### 4️⃣ sw(存储,写内存)
`M[R[rs] + SEXT(imm16)] = R[rt]`
- IF → ID → EX 算地址 → MEM 写内存
- 不写寄存器,所以 WB 段空着 ✈️

### 5️⃣ beq(条件分支)
- IF → ID → EX 比较 rs 和 rt + 算分支目标地址
- **MEM 段干了一件怪事:写 PC** ✨
- WB 段空着 ✈️

> 💡 为啥 beq 要在 MEM 写 PC?
> 因为 beq 写 PC 的延迟 **小于** 真正的内存访问时间,所以塞在 MEM 段既不耽误时间,又能让它跟 lw/sw 的段数对齐

### 6️⃣ j(无条件跳转)
- 直接把目标地址塞给 PC
- 本来 EX 段就能搞定,但**为了凑齐 5 段对齐**,MEM 和 WB 都得空着

---

## 📌 关键设计原则(必考)

**为什么必须是 5 段?**
- 每条指令对每个功能部件**最多用一次**(比如 lw 不能在 MEM 段又去读内存)
- 相同功能部件必须在**固定阶段**使用(比如寄存器写口永远在第 5 段)

**统一 5 段的代价**:有些指令会"浪费"段(插空段),但好处是**控制逻辑简单、IF/ID/EX/MEM/WB 这 5 个模块可以复用**——这就是 MIPS 流水线设计的精髓。
