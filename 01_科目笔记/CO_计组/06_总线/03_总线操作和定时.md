## 6.2 总线事务和定时 📚

### 6.2.1 总线事务

#### 📌 基本概念

在总线上，**主设备**（如 CPU、DMA 控制器）与**从设备**（如主存、I/O 设备）之间完成一次完整的信息交换过程，称为一个**总线事务**。

**典型类型**：存储器读、存储器写、I/O 读/写、中断响应等。

#### 🔹 三个基本阶段（依据历年真题)

| 阶段  | 名称                  | 内容                                 |
| --- | ------------------- | ---------------------------------- |
| 1️⃣ | **地址传送阶段**          | 主设备将目标地址和操作类型（读/写）通过总线传送给从设备       |
| 2️⃣ | **从设备响应阶段**（数据准备阶段） | 从设备根据地址准备数据（耗时由设备特性决定，题中未提及时通常可忽略） |
| 3️⃣ | **数据传送阶段**          | 完成实际数据在总线上的传输                      |

#### (1) 非突发传输与突发传输

##### 🔸 非突发传输

- 每次仅传输**一个数据单元**（通常为一个总线宽度的数据）
- 每次传输都必须独立经历完整的三阶段流程
- 即使连续读取多个相邻数据，也需要**重复发送地址**
- 🚫 缺点：地址开销大、效率较低
- 💡 口诀："**一次地址，一次数据**"

##### 🔸 突发传输

- 用于高效传输**连续成块的数据**
- 事务开始时，主设备**仅发送数据块的首地址**
- 在**不释放总线**的前提下，连续传送多个数据单元
- 后续地址由**硬件自动递增生成**（首地址+1、首地址+2……）
- 无须重复使用地址线
- 💡 口诀："**一次地址，多次数据**"
- ✅ 应用场景：高速存储器访问（如 SDRAM 行读取、Cache 块填充）

**🔺 对比总结**：在相同总线宽度和时钟频率下，突发传输省去了多次地址传送开销，**显著提升了有效带宽**。
#### (2) 串行传输与并行传输

数据在总线上的物理传输可采用串行或并行两种方式。
##### 🔸 串行传输
- 数据按**比特位**依次顺序传输
- 通常仅使用**一条双向线路**或**两条单向线路**（发送/接收各一）
- ✅ 优点：引脚少、布线简单、抗干扰能力强
- ✅ 适合**长距离通信**（如 USB、PCIe、SATA）
- 又可分为**同步串行通信**和**异步串行通信**

###### 1) 同步串行通信
- 由**发送方时钟直接控制接收方时钟**，实现位同步
- 收发双方的时钟**严格一致**
- 仅在数据块首尾添加开始和结束标记
- ✅ 传输效率高
- 🚫 硬件实现复杂，成本较高

###### 2) 异步串行通信
- 收发双方使用**独立时钟**，无须严格同步
- 每个字符独立传输
- 通过**起始位**（逻辑 0）标识开始，**停止位**（逻辑 1）标识结束
- 当通信线路空闲时，保持**逻辑 1** 状态
- 发送字符时：先发一个逻辑 0 作为起始位 → 接收方检测到低电平后开始接收
- 数据位从**最低位**开始逐位发送
- 发送完数据位后，可选发送一位**奇偶校验位**（用于差错检测）
- 随后发送**停止位**表示该字符的结束

##### 🔸 并行传输
- 利用**多条数据线**同时传输多个比特位（如 32 位、64 位总线）
- 理论上**单周期**即可完成一个字的传输
- ✅ 短距离内延迟低、吞吐高
- 🚫 随着频率提高，**信号串扰和时序偏移**问题加剧，限制工作频率提升
- ✅ 适合**板级或芯片级**的短距离通信（如早期 PCI、内存总线）

> **⚠️ 注意**：并行传输并不总是比串行传输更快。
> - 并行总线：受限于电气特性，工作频率难以持续提高
> - 串行传输：可通过提升频率实现更高的总带宽
> - 👉 **现代高速接口多采用串行化设计**

### 6.2.2 总线定时

#### 📌 基本概念
总线定时是指总线上主设备与从设备在交换数据时，用于协调双方操作时序的**控制协议**。其实质是一种**时序规则**，主要有以下四种方式：

#### 1️⃣ 同步定时方式

采用**系统统一的时钟信号**来协调发送方和接收方的传送定时关系。每个时钟间隔构成一个**总线周期**，每次数据传送在一个总线周期内完成。

| 项目      | 内容                                                |
| ------- | ------------------------------------------------- |
| ✅ 优点    | 传送速度快，传输速率较高；总线控制逻辑简单                             |
| 🚫 缺点   | 主从设备属于**强制性同步**；缺乏应答/握手机制；无法根据从设备实际状态动态调整时序，可靠性较差 |
| 🎯 适用场景 | 总线长度较短，且所连接各部件的**存取时间比较接近**的系统                    |

#### 2️⃣ 异步定时方式

不依赖统一的时钟信号，而是通过主从设备之间的**握手信号**实现定时控制：

- 主设备发出"**请求**"信号
- 从设备准备就绪后，发出"**回答**"信号

|项目|内容|
|---|---|
|✅ 优点|总线周期长度可变；能可靠连接**工作速度差异较大**的设备；自适应性强|
|🚫 缺点|控制逻辑复杂；因多次信号交互，整体传输速率较低|
|🎯 适用场景|连接速度差异大、对可靠性要求较高而对速率要求不苛刻的系统|

##### 三种异步互锁方式

根据"请求"与"回答"信号的撤销是否互锁，异步定时可分为三类：

| 方式          | 主设备撤销"请求"             | 从设备撤销"回答"            | 可靠性    |
| ----------- | --------------------- | -------------------- | ------ |
| **(a) 不互锁** | 预设时延 t₁ 后自行撤销         | 时延 t₂ 后自动撤销          | 最低     |
| **(b) 半互锁** | 必须收到"回答"后才撤销（**有互锁**） | 时延 t₂ 后自动撤销（**无互锁**） | 中等     |
| **(c) 全互锁** | 需收到"回答"才撤销            | 需确认"请求"已撤销后才撤销       | **最高** |

📌 **记忆要点**：全互锁 = 双方都等对方先撤销，所以**最慢但最可靠**；不互锁 = 双方各撤各的，所以**最快但最不可靠**

#### 3️⃣ 半同步定时方式

结合了**同步与异步**的优点：

- 地址、命令、数据的发送**严格参照系统时钟前沿**（如上升沿）
- 接收方通常在**时钟后沿**（如下降沿）进行识别
- 增设一条 **Wait 信号线**，允许慢速从设备反馈准备状态
- 主设备在时钟上升沿检测 Wait 信号状态
    - 若 Wait **无效（高电平）**：表示数据未就绪，主设备将**插入等待周期**
    - 直到 Wait **有效（低电平）**：才从数据线读取数据

| 项目      | 内容                            |
| ------- | ----------------------------- |
| ✅ 优点    | 在统一时钟下工作，控制比异步方式简单，可靠性较高      |
| 🚫 缺点   | 系统时钟频率**受限于最慢设备**，整体速度不高      |
| 🎯 适用场景 | 包含多种速度差异较大设备、但**性能要求不高**的简单系统 |

> **📍 重要补充**：上述三种定时方式（同步、异步、半同步）均采用"**独占式事务模型**"——从主设备发出请求到传送结束，总线全程被该事务占用。然而，在从设备准备数据阶段，总线虽被占用却处于空闲状态，造成**资源浪费**。

#### 4️⃣ 分离式定时方式

将一个总线事务拆分为**两个独立子阶段**：**请求阶段**与**应答阶段**，两阶段之间**释放总线**。

|阶段|内容|
|---|---|
|**请求阶段**|主设备 A 获得总线使用权，**发送地址和命令后立即释放总线**，供其他设备使用|
|**应答阶段**|从设备 B 准备好数据后，**主动申请总线**，并以主设备身份将数据发回给 A|

📌 **关键特点**：两个子阶段均为**单向信息流**，且总线在准备期间可被其他事务使用。

|项目|内容|
|---|---|
|✅ 优点|显著减少总线空闲等待时间，**提高总线利用率**|
|🚫 缺点|控制逻辑复杂，协议开销大，对总线仲裁和事务管理机制要求高|
|🎯 适用场景|**多主设备竞争激烈**且**从设备响应延迟较大**的高性能系统|
