### 一、引导流程

```

① CPU 加电
   └─→ 跳转到 BIOS 入口地址

② BIOS 自检 + 找启动盘
   └─→ 读取启动硬盘的 第 0 扇区 = MBR 到内存 0x7C00

③ MBR 中的引导程序执行
   └─→ 扫描分区表，找到 "活动分区"（可引导分区）
   └─→ 读取该活动分区的 第 0 扇区 = PBR 到内存

④ PBR 中的引导程序执行
   └─→ 加载该分区上的 OS 引导程序（如 NTLDR / BOOTMGR / GRUB）

⑤ OS 引导程序执行
   └─→ 加载 OS 内核（如 vmlinuz / ntoskrnl.exe）到内存

⑥ 内核初始化 OS（创建中断向量表等）
   └─→ 启动登录界面 → 启动完成
```

### 步骤 ① CPU 加电

#### CPU 复位向量

- CPU 上电瞬间，硬件把所有寄存器强制设为初始值
- **CS = F000H，IP = FFF0H**，因此第一条指令地址 = `CS×16 + IP` = **`FFFF0H`**
- 这个地址指向 **BIOS ROM 芯片**的尾部（ROM 映射到内存最高 64KB 区域）

#### 关键考点

| 考点           | 内容                            |
| ------------ | ----------------------------- |
| 入口地址         | **FFFF0H**（即物理地址顶端）           |
| 工作模式         | **实模式**（20 位地址总线，只能访问 1MB 内存） |
| CPU 看到的第一条指令 | 通常是 `JMP` 跳到 BIOS 真正的初始化代码    |

### 步骤 ② BIOS 自检 + 找启动盘

#### BIOS 的功能

| 子任务              | 作用                                                                             |
| ---------------- | ------------------------------------------------------------------------------ |
| **POST 自检**      | 检测 CPU、内存条、显卡、键盘、磁盘控制器等                                                        |
| **建立中断向量表（IVT）** | BIOS 在实模式下用 0~3FFH 这 1KB 内存建立 IVT，存放中断服务程序入口（这是 BIOS 自己的 IVT，跟 OS 创建的 IDT 不同 ） |
| **初始化硬件**        | 让显卡显示、键盘可输入、磁盘可读                                                               |
| **读取 CMOS 配置**   | 知道启动顺序（HDD/USB/CD/Network）                                                     |


### 步骤 ③ MBR 引导：找活动分区

#### MBR 的结构

```
┌──────────────────────────────────────────────────────────┐
│ MBR = 硬盘第 0 扇区（512 字节）                            │
├──────────────┬────────────────────────┬─────────────────┤
│ 引导程序      │   分区表                │   有效标志       │
│ 446 字节     │   64 字节（4 项×16 字节） │   2 字节        │
│              │                        │   55AA          │
└──────────────┴────────────────────────┴─────────────────┘
```
#### MBR 引导程序做的事

1.扫描分区表 4 个表项

2.找到**活动标志为 80H**的那一项

3.用 **INT 13H** 读取该分区的**起始 LBA 扇区**（即该分区的第 0 扇区 = PBR）

4.加载到内存（通常在 `0x0000:0x7C00` 或 `0x7E00`），跳转执行

### 步骤 ④ PBR 引导：加载 OS 引导程序

#### PBR 的结构（以 FAT 文件系统为例）

```
┌──────────────────────────────────────────────────────────┐
│ PBR = 分区第 0 扇区（512 字节）                           │
├──────────────┬──────────────┬────────────────────────────┤
│ 跳转指令(3B)  │ OEM 名称(8B)  │   BPB 参数表                │
│              │              │   （描述文件系统参数）       │
├──────────────┴──────────────┴────────────────────────────┤
│      引导程序代码（约 448 字节）                           │
├──────────────────────────────────────────────────────────┤
│      结束标志 55 AA                                       │
└──────────────────────────────────────────────────────────┘
```


> 📌 **MBR 没有 BPB，PBR 才有 BPB** —— 这是常考点。

#### PBR 引导程序做的事

读取该分区根目录下的 **OS 引导程序** 文件：

- Windows XP：`NTLDR`
- Windows Vista+：`BOOTMGR`
- Linux：`GRUB`（位于 `/boot/grub/`）

把它加载到内存并执行。

### 步骤 ⑤ OS 引导程序：加载内核

#### GRUB 的三阶段（Linux）

| 阶段            | 位置                | 大小   | 作用                            |
| ------------- | ----------------- | ---- | ----------------------------- |
| **Stage 1**   | MBR 前 446 字节      | 446B | 加载 Stage 1.5                  |
| **Stage 1.5** | MBR 之后的空闲扇区       | 几 KB | 识别文件系统（EXT4/FAT 等），加载 Stage 2 |
| **Stage 2**   | `/boot/grub/` 目录下 | 较大   | 显示启动菜单、加载内核和 initramfs        |


### 步骤 ⑥ 内核初始化（408 重点中的重点 ⭐⭐⭐）

#### 6.1 架构相关初始化（汇编阶段）

以 Linux 为例，从 `head_64.S` 开始：

| 工作                       | 说明                  |
| ------------------------ | ------------------- |
| 检测 CPU 类型和支持的特性          | 用 CPUID 指令          |
| 初始化**临时页表**              | 先建立恒等映射，让内核能在保护模式下跑 |
| 启用分页机制                   | 写 CR0、CR3、CR4 寄存器   |
| 设置栈指针                    | C 代码需要栈             |
| 跳到 C 代码 `start_kernel()` | 正式进入内核              |

#### 6.2 内核初始化（`start_kernel()`）⭐

按调用顺序：

```
start_kernel()
  ├── lockdep_init()           // 锁依赖检测
  ├── setup_arch()             // 架构相关（内存布局等）
  ├── setup_command_line()     // 解析启动参数
  ├── trap_init()              // ⭐ 设置 IDT 中断描述符表
  ├── mm_init()                // ⭐ 内存管理初始化（伙伴系统、slab）
  ├── sched_init()             // ⭐ 初始化进程调度器
  ├── init_idle()              // 创建 PID=0 的 idle 进程
  ├── init_IRQ()               // 初始化中断处理
  ├── vfs_caches_init()        // 虚拟文件系统缓存
  ├── signals_init()           // 信号机制
  ├── proc_root_init()         // /proc 文件系统
  ├── driver_init()            // 驱动模型
  ├── rest_init()              // 创建 PID=1 和 PID=2
  │     ├── kernel_init → PID 1 = init 进程
  │     └── kthreadd   → PID 2 = 内核线程守护
```

#### 6.3 关键数据结构的创建 ⭐（408 常考点）

|数据结构|何时创建|作用|
|---|---|---|
|**IDT（中断描述符表）**|`trap_init()`|替代 BIOS 的 IVT，记录所有中断/异常处理函数|
|**GDT（全局描述符表）**|`setup_arch()`|段描述符管理|
|**内核页表**|`head_64.S` + `mm_init()`|虚拟地址到物理地址映射|
|**PCB 池**|`fork_init()`|后续创建进程的 PCB 都来自这个池|
|**就绪队列**|`sched_init()`|调度器管理所有可运行进程|

#### 6.4 用户空间初始化（`kernel_init`，PID=1）

1.**挂载 initramfs** 到临时根 `/`


3.找到真正的根设备后，调用 `mount()` **挂载根文件系统**

4.`chroot` 切换到真实根

5.执行 `/sbin/init`（现代 Linux 是 **systemd**）

6.systemd 启动各种 `.service` 服务

7.启动登录管理器（getty / GDM）

8.用户登录 → shell/desktop 出现 → 启动完成 ✅
